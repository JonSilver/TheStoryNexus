# Advanced

Nothing here is needed to write a novel. It's here for when you want to change how the machinery behaves, get your words out, or run the whole thing off your own hardware.

## The AI Actions drawer

**More → AI Actions (advanced overrides)** lists every action the app can run, each marked **built-in** or **customised**, and noting which ones follow your story voice.

Pick a scope first:

- **All stories** — a global override, used everywhere unless a story overrides it too.
- **This story** — applies to the current story only, and beats the global one.

Tap an action to edit it. Its template is a list of role-tagged messages (**system**, **user**, **assistant**); edit the text, add messages with **+ message**, remove ones you don't want. Below them sit **Temperature** and **Max tokens**. **Save override** stores it, **Reset to built-in** throws your version away, **Cancel** leaves everything alone.

### Variables

The header of the editor lists the `{{variables}}` that action is allowed to use — the same context the built-in template draws on. They're substituted at generation time:

| Action | Follows story voice | Variables available |
| --- | --- | --- |
| Scene Beat | Yes | `matched_entries` `summaries` `recent_prose` `pov` `command` |
| Continue Writing | Yes | `matched_entries` `summaries` `recent_prose` `pov` |
| Rework / Expand / Shorten | Yes | `selection` `recent_prose` `pov` `story_language` |
| Brainstorm | Yes | `matched_entries` `chat_history` `user_message` |
| Summarise Chapter | No | `chapter_content` |
| Extract Bible Entries | No | `chapter_content` `user_message` `matched_entries` |
| Propose Bible Updates | No | `chapter_content` `matched_entries` |

An unknown variable is a **save-time error**, not a silent passthrough — you'll be told rather than discovering a literal `{{summarie}}` in your prose three chapters later. If an override somehow becomes invalid, generation falls back to the built-in template rather than failing.

> [!NOTE]
> **Max tokens** is a ceiling, not a promise: a request can never reserve more than half the model's context window for output, and the context the app assembles is trimmed to fit whatever's left — oldest prose first, then the lowest-ranked bible entries, then the most distant chapter summaries.

> [!TIP]
> Before you rewrite a template, use the **eye** icon on a scene beat to read the resolved prompt. Most disappointing output is a context problem, not a wording problem.

## Exporting your story

**More → Export story** downloads the whole story — every chapter in order, chapter titles as headings — in whichever format you tap:

| Format | Notes |
| --- | --- |
| **Markdown** | Headings, lists, emphasis and rules as Markdown |
| **Text** | Plain prose, no markup |
| **HTML** | Escaped, standalone markup |
| **EPUB** | A real e-book, built on the server: cover page with your title, author and synopsis, a table of contents, and any images embedded in the file |

Scene beats are omitted from every format; they're instructions to the AI, not part of the book.

## Running a local model

AI generation happens on the **server**, not in your browser. The local model URL you set in **AI Settings → Local Models → Advanced Settings** must therefore be reachable *from wherever The Story Nexus server is running* — not from your phone. That's what makes local models work from a phone at all.

- **Server and LM Studio on the same machine:** the default `http://localhost:1234/v1` is right.
- **Docker on Linux, model on the host:** `localhost` inside a container is the container. Add a host gateway to `docker-compose.yml` and use it:

    ```yaml
    services:
        app:
            extra_hosts:
                - "host.docker.internal:host-gateway"
    ```

    Then set the URL to `http://host.docker.internal:1234/v1`.

- **Docker Desktop (Mac or Windows):** `http://host.docker.internal:1234/v1` works as-is.
- **Model on another machine on your network:** use that machine's LAN address, e.g. `http://192.168.1.50:1234/v1`, and make sure the model server is listening on the network rather than only on loopback.

Saving the URL tests the connection and fetches the model list. If saving fails, the server can't reach the model host — that's the thing to fix, and `docs/DEPLOYMENT.md` has the full detail.

## Writing from other devices

The app is a normal web app on your network. Find your server's address and open it from anything with a browser:

```bash
# Linux/Mac
hostname -I

# Windows
ipconfig
```

Then visit `http://YOUR-SERVER-IP:3000` — for example `http://192.168.1.100:3000` — from a phone or tablet on the same network. Your work, your bible and your keys all live on the server, so a phone is just another window onto the same desk.

> [!WARNING]
> There's no login. Anyone who can reach that address can read and edit everything. It's built for a trusted home network — don't expose the port to the internet.

## Two devices, one chapter

Editing the same chapter on two devices in sequence is fine — each save carries the revision it was based on. If a chapter has moved on underneath you, saving stops, the editor says **This chapter was changed on another device**, and offers **Reload**. Nothing gets silently overwritten. Editing the same chapter on two devices *simultaneously* isn't supported.
