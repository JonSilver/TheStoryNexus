# Advanced

Nothing here is needed to write a novel. It's for changing how the machinery behaves, getting your words out safely, running your own models, and understanding what went wrong when something does.

## AI actions

**Settings → AI actions (advanced overrides)** lists every action the app runs, each marked **built-in** or **customised**, and whether it follows your story voice. Choose a scope — **All stories**, or **This story** (which beats the global one) — then tap an action:

- **Model for this action** — e.g. a small fast model for summaries and your best model for prose. Leave it unset to use your default model.
- **Temperature**, **Top-p**, **Freq. penalty**, **Pres. penalty**, **Max tokens** — blank means the model's own default.
- **The template** — role-tagged messages (system, user, assistant) you can edit, add to or remove.

**Save override** stores it; **Reset to built-in** discards yours.

### Variables

Each action's template may use these `{{variables}}`, filled in when it runs:

| Action                       | Story voice | Variables                                                                                |
| ---------------------------- | ----------- | ---------------------------------------------------------------------------------------- |
| Continue Writing             | Yes         | `matched_entries` `summaries` `recent_prose` `pov` `story_language` `guidance`           |
| Rework / Expand / Shorten    | Yes         | `selection` `recent_prose` `pov` `story_language` `guidance`                             |
| Ask (free-form on selection) | Yes         | `selection` `recent_prose` `pov` `story_language` `user_message` `guidance`              |
| Scene Beat                   | Yes         | `matched_entries` `summaries` `recent_prose` `pov` `command` `story_language` `guidance` |
| Brainstorm                   | Yes         | `matched_entries` `summaries` `chapter_content` `chat_history` `user_message`            |
| Summarise Chapter            | No          | `chapter_content`                                                                        |
| Extract Bible Entries        | No          | `chapter_content` `user_message` `matched_entries` `guidance`                            |
| Propose Bible Updates        | No          | `chapter_content` `matched_entries`                                                      |
| Check Continuity             | No          | `chapter_content` `matched_entries`                                                      |
| Merge Bible Entries          | No          | `user_message`                                                                           |

`guidance` carries a Refine steer. An unknown variable is refused when you save, and if an override ever becomes invalid the built-in template is used instead.

> [!TIP]
> Before rewriting a template, open the **eye** on a scene beat to read exactly what's sent. Disappointing output is more often a context problem than a wording problem.

## When generation goes wrong

Every message names the model and server involved and says what to do:

| You see                                             | It means                                                                                                                                       |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| _…doesn't have this model_                          | The model was renamed or removed on the server. The message says whether your default or an action's override chose it — fix that in Settings. |
| _…the API key was rejected_                         | Check the key under AI providers & models.                                                                                                     |
| _…rate-limiting or too busy_                        | Wait a moment and **Try again**.                                                                                                               |
| _…couldn't reach the model server_                  | The server is down, or its address in Settings is wrong.                                                                                       |
| _…didn't start responding within 3 minutes_         | The request reached the server but it never began to answer — overloaded, still loading the model, or stuck.                                   |
| _…produced no text_ / _…without producing any text_ | Often a "thinking" model spending its whole budget on hidden reasoning — raise **Max tokens** for that action, or use a non-thinking model.    |
| _…stopped sending text partway through_             | The stream stalled; what arrived is kept, marked incomplete.                                                                                   |
| _Couldn't reach The Story Nexus server_             | The app's own server didn't answer — it may have stopped, or this device lost its connection.                                                  |

Every failure offers **Try again** in place, and text that arrived before a failure is kept, marked incomplete. Continue, the selection actions, scene beats, Brainstorm and Merge keep your earlier results too, so a failed or worse retry never costs a good one. While text is arriving, a pause of more than ten seconds is shown, and **Stop** is always there.

## Exports, backups and restoring

**Story → Export** downloads the story in the format you tap:

| Format            | Notes                                                                                                                  |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------- |
| **Markdown**      | Headings, lists, emphasis and dividers                                                                                 |
| **Text**          | Plain prose                                                                                                            |
| **HTML**          | Standalone markup                                                                                                      |
| **EPUB**          | A real e-book: cover page, table of contents, images embedded                                                          |
| **JSON (backup)** | Everything about this story — chapters, bible, notes, brainstorm chats, per-story AI overrides and images — restorable |

Scene beats and pending suggestions are left out of the book formats; if any have unaccepted takes, the app warns you first.

- **Restore a story:** **Story → Switch story → JSON**, pick the file. It comes back as a new story titled "… (Imported)", restored completely or not at all.
- **Series:** **Settings → Series** — each series has a download button for a backup of the series bible and every story in it; **Import Series** restores one.
- **Everything:** **Settings → Backup → Download backup** is a consistent snapshot of the whole database, safe to take while you write. Images live separately under `data/assets/` on the server — back that folder up too.

## Series

Put a story in a series under **Story → Details, series & voice** (pick one, or **+ New series…**). Series-level bible entries then reach every story in it, and the library groups stories by series. **Settings → Series** lists them, with create, import and export.

## Running a local model

Generation runs on the **server**, so the **Server URL** under **AI providers & models → Local Models** must be reachable _from wherever The Story Nexus server runs_ — not from your phone. Any OpenAI-compatible server works: Ollama (usually port 11434), LM Studio (1234), llama.cpp, vLLM and others.

- **Same machine as the app:** e.g. `http://localhost:11434/v1`.
- **Docker on Linux, model on the host:** `localhost` inside the container is the container. Add a host gateway to `docker-compose.yml` and use `http://host.docker.internal:<port>/v1`:

    ```yaml
    services:
        app:
            extra_hosts:
                - "host.docker.internal:host-gateway"
    ```

- **Docker Desktop (Mac or Windows):** `http://host.docker.internal:<port>/v1` works as-is.
- **Another machine on your network:** use its LAN address, and make sure the model server listens on the network, not just on loopback.

Saving the URL tests it and fetches the models; if that fails, the error says why. `docs/DEPLOYMENT.md` has more.

## Writing from other devices

Open the app's address from any browser on your network — `http://YOUR-SERVER-IP:3000` for the Docker or production server (find the IP with `hostname -I` on Linux/Mac or `ipconfig` on Windows). Every screen has its own address, so a chapter you bookmark on your laptop opens on your phone too.

> [!WARNING]
> There's no login. Anyone who can reach that address can read and edit everything. Keep it to a trusted home network; don't expose it to the internet.

## Two devices, one chapter

Each save carries the version of the chapter it was based on. If the chapter has changed elsewhere in the meantime, saving stops and the editor locks with **This chapter was changed elsewhere**: **Download my version** keeps what's on your screen, **Reload** shows the other one. Nothing is overwritten silently.
